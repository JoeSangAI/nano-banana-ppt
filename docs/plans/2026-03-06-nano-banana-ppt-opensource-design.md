# Nano Banana PPT 开源与版权保护设计方案

## 1. 背景与目标
- **目标**: 将 `nano_banana_ppt` 工具开源分享给混沌的老师，同时保护作者的著作权，并建立接受他人贡献（Contributions）的机制。
- **用户**: 桑卓豪 Joe
- **核心诉求**: 
  - 明确代码归属权。
  - 允许他人使用和修改代码。
  - 希望别人修改代码后能反馈/合并回原项目（通过 Pull Request 流程）。

## 2. 方案选型 (已确认: 选项 C - 宽松开源 + 贡献指南)
采用业界最广泛使用的开源协议（如 MIT License），结合明确的 `CONTRIBUTING` 指南。
- **License (开源协议)**: 采用 MIT 协议。它允许任何人免费使用、修改和分发代码，甚至用于商业用途，但**必须保留原作者的版权声明**。这样既能最大程度促进分享，又在法律上宣示了“这是 Joe 的作品”。
- **版权所有者**: 桑卓豪 Joe

## 3. GitHub 协作流程设计
为了让作者知道“别人改了代码”并将其纳入主线，我们需要在项目中说明 GitHub 的标准协作流程（Pull Request）：
1. **Fork**: 其他人将你的仓库复制一份到他们自己的 GitHub 账号下。
2. **Clone & Modify**: 他们在自己的仓库里修改代码。
3. **Pull Request (PR)**: 他们修改完成后，向你的仓库发起一个“合并请求 (PR)”。
4. **Review & Merge**: 这时**你**会收到 GitHub 的邮件和站内通知。你可以查看他们改了什么代码，如果觉得改得好，点击 `Merge pull request` 就可以把他们的代码合并到你的项目中，他们也会因此成为你项目的 `Contributor`（贡献者）。
